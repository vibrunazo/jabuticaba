# Content Schema v0 (draft)

Status: **draft for discussion**. This document specifies how jabuticaba items are
stored on disk and which rules every file must follow. The scoring rules that
consume this data are in [01-index-methodology-v0.md](01-index-methodology-v0.md).

## 1. Principles

1. **Zod is the single source of truth.** The schema is written once in TypeScript
   with Zod. Everything else is generated from it: TypeScript types (`z.infer`),
   the JSON Schema used by editors, and the validator. Nothing is hand-written twice.
2. **Store inputs, never outputs.** Files hold facts, ratings and sources. Scores,
   grades and counts are always computed.
3. **Language-neutral data in JSON, all translatable text in one Markdown file per
   locale.** Adding a language means adding files, not changing the schema.
4. **Every item is a self-contained folder.** An agent working on one item only
   needs to read that folder.
5. **English identifiers everywhere.** Portuguese appears only in values inside
   `pt.md`.
6. **Validation errors are actionable.** Every rule has a stable code, and every
   message says how to fix it.

## 2. Directory layout

```
content/                               # data only; no code
├── jabuticabas/
│   └── capybara/                      # folder name == item id
│       ├── item.json                  # language-neutral data
│       ├── pt.md                      # pt-BR text (required)
│       └── en.md                      # English text (optional)
└── reference/
    ├── places.json                    # ISO 3166-1 alpha-2 codes + sovereign-state lookup
    └── brazil-states.json             # the 27 federative units

schemas/
└── item.schema.json                   # GENERATED from Zod; referenced by every item.json

data/
├── index-results.csv                  # GENERATED by `pnpm index`
└── geo/world.topo.json                # GENERATED by `pnpm geo:build`
```

Content lives outside `src/` on purpose. Agents changing code rarely touch data by
accident, and the other way round.

All generated files are **committed**. CI regenerates them and fails if the
committed copy differs (rules J070–J072).

## 3. Shared types

| Type          | Format                                                        | Example                          |
|---------------|---------------------------------------------------------------|----------------------------------|
| `Id`          | kebab-case ASCII: `^[a-z0-9]+(-[a-z0-9]+)*$`, max 60 chars     | `electric-shower`                |
| `Date`        | `YYYY-MM-DD`                                                  | `2026-09-25`                     |
| `PartialDate` | `YYYY`, `YYYY-MM` or `YYYY-MM-DD`                             | `2023-05`                        |
| `PlaceCode`   | ISO 3166-1 alpha-2, present in `places.json`, never `BR`       | `GF`                             |
| `StateCode`   | Brazilian UF code, present in `brazil-states.json`            | `SP`                             |
| `Rating`      | integer 0–4, **or** `{ "min": a, "max": b }` with `a < b`      | `3`, `{ "min": 1, "max": 2 }`    |
| `LevelRange`  | a presence level, **or** `[low, high]` with `low` below `high` | `"regional"`, `["marginal", "regional"]` |
| `Evidence`    | `{ "sources": Id[], "editorial"?: true }`                      | see below                        |

### Ranges

Every range has the same meaning: the true value is somewhere between the two ends.
The scoring module takes the ends for the low and high bounds, and the midpoint for
the point estimate.

### `Evidence`

Every input the index uses (each presence entry, `intensity`, `awareness`,
`brazilStates` entries) carries evidence:

- `sources`: ids of entries in the item's `sources` list.
- `editorial: true`: the value is the editors' judgment, with no source that
  supports it directly. **Must** have `sources: []` (rule J036). Editorial inputs
  score 0 in the evidence grade.

## 4. `item.json`

| Field                | Type                         | Req. | Notes |
|----------------------|------------------------------|------|-------|
| `$schema`            | string                       | yes  | Always `"../../../schemas/item.schema.json"`. Gives editors and agents autocomplete and inline errors. |
| `id`                 | `Id`                         | yes  | English, stable forever, equals the folder name. URLs use per-locale slugs, so the id never has to be renamed for SEO. |
| `status`             | `mock` \| `draft` \| `published` | yes  | See section 8. |
| `methodologyVersion` | string `^\d+\.\d+$`          | yes  | Methodology version the inputs were last reviewed against. |
| `lastReviewed`       | `Date`                       | yes  | Not in the future. |
| `category`           | `Category`                   | yes  | Exactly one; see section 6. |
| `since`              | integer year, or `{ min, max }` | no  | Descriptive, not scored. |
| `presence`           | `PresenceEntry[]`            | yes  | May be empty (an item that exists nowhere else). |
| `brazilStates`       | `StateEntry[]`               | no   | Presence inside Brazil, for subnational maps. Not scored. |
| `intensity`          | `IntensityInput`             | yes  | Scored. |
| `awareness`          | `AwarenessInput`             | yes  | Not scored. |
| `sources`            | `Source[]`                   | yes  | May be empty only for `draft` items. |
| `related`            | `Id[]`                       | no   | Other item ids. The site computes backlinks, so there is no need to list both directions. |

`intensity` and `awareness` are top-level fields, not grouped under a shared key.
Grouping them would suggest to agents that both are scored.

### `PresenceEntry`

| Field      | Type         | Req. | Notes |
|------------|--------------|------|-------|
| `place`    | `PlaceCode`  | yes  | Unique within the item. |
| `level`    | `LevelRange` | yes  | `widespread`, `regional`, `marginal`, `imported`, `absent`. |
| `sources`  | `Id[]`       | yes  | From `Evidence`. |
| `editorial`| `true`       | no   | From `Evidence`. |

Level order, from low to high: `absent` < `imported` < `marginal` < `regional` <
`widespread`. In a range, `low` must be below `high`.

### `StateEntry`

Same shape as `PresenceEntry`, but with `state: StateCode` instead of `place`, and
the levels `widespread`, `regional`, `marginal`, `absent`.

### `IntensityInput`

| Field      | Type                           | Req. | Notes |
|------------|--------------------------------|------|-------|
| `value`    | `Rating`                       | yes  | See methodology 3.2. |
| `ratio`    | positive number, or `{ min, max }` | no | Brazil's prevalence ÷ the highest other place. When present, `value` must match the ratio band (warning J040). |
| `sources`  | `Id[]`                         | yes  | |
| `editorial`| `true`                         | no   | |

### `AwarenessInput`

`{ value: Rating, sources: Id[], editorial?: true }`. See methodology 7.1.

### `Source`

| Field        | Type          | Req. | Notes |
|--------------|---------------|------|-------|
| `id`         | `Id`          | yes  | Unique within the item. **Descriptive**, e.g. `ibge-census-2022`, `tse-resolution-23669`. Never `src-1`: descriptive ids make prose citations readable and reduce agent mix-ups. |
| `type`       | `SourceType`  | yes  | Drives the evidence grade; see section 6. |
| `title`      | string        | yes  | In the source's original language. Never translated. |
| `publisher`  | string        | yes  | |
| `authors`    | string[]      | no   | |
| `url`        | https URL     | yes  | |
| `archiveUrl` | https URL     | published only | A `web.archive.org` or `archive.ph` snapshot. |
| `published`  | `PartialDate` | no   | |
| `accessed`   | `Date`        | yes  | |
| `language`   | BCP 47 tag    | yes  | `pt`, `en`, `es`, `pt-PT`… Displayed as "(em espanhol)" / "(in Spanish)". |
| `locator`    | string        | no   | Page, table or section, e.g. `"Table 3.2"`, `"p. 41"`. |

## 5. Locale files: `pt.md`, `en.md`

One file per locale, named by the locale's route code. `pt.md` is required. The
YAML frontmatter holds every short translatable string; the body holds the article.

### Frontmatter

| Field               | Type                                 | Req. | Notes |
|---------------------|--------------------------------------|------|-------|
| `translationStatus` | `original` \| `machine` \| `reviewed` | yes  | Exactly one locale per item is `original` (J051). A `machine` translation shows a small notice on the page. |
| `slug`              | `Id`                                 | yes  | ASCII only, no accents: `chuveiro-eletrico`. Unique per locale. |
| `title`             | string, 1–80 chars                   | yes  | |
| `summary`           | string, 1–200 chars                  | yes  | One sentence. Used on cards, in meta descriptions and in social preview images. |
| `definition`        | string, 1–400 chars                  | yes  | The precise scope that gets scored (methodology section 2). |
| `justifications`    | `{ intensity: string, awareness: string }` | yes | Why each rating has its value. |
| `presenceNotes`     | map of `PlaceCode` → string           | no   | Explains specific presence entries. Keys must exist in `presence`. |
| `brazilStatesNote`  | string                               | no   | One note for the subnational map. |

All locale files of an item must have **the same keys**, including the same set of
`presenceNotes` keys (J052). A note added in Portuguese forces a translation.

Convention: always double-quote string values in frontmatter. Portuguese text is
full of colons, which break unquoted YAML.

### Body

- Markdown only; no raw HTML.
- Headings start at `##`. The page renders the title as `h1`.
- **Citations** use Pandoc syntax: `[@ibge-census-2022]`, or
  `[@ibge-census-2022; @tse-resolution-23669]`, optionally with a locator:
  `[@ibge-census-2022, p. 41]`. The build turns them into numbered footnotes
  linked to the source list.
- **Links to other items** use the item id with a custom scheme:
  `[capivaras](jabuticaba:capybara)`. The build resolves it to the right localized
  URL, so authors and agents never need to know slugs.
- Bare external links are discouraged (J055). If it supports a claim, it should be
  a source.

## 6. Enums

### `Category`

Defined once in the Zod schema. Display labels are in the UI dictionary, and the
type checker ensures every category has a label in every locale.

| Id         | Scope                                                  |
|------------|--------------------------------------------------------|
| `nature`   | Fauna, flora, landscapes                               |
| `food`     | Food, drink, eating habits                             |
| `home`     | Household objects and domestic habits                  |
| `urban`    | Cities, buildings, infrastructure, transport           |
| `culture`  | Customs, festivities, language, sports, media          |
| `politics` | Elections, parliament, parties, public administration  |
| `justice`  | Courts, laws, the legal system                         |
| `economy`  | Money, taxes, public finance, business, payments       |

### `SourceType`

| Id             | Strength | Examples |
|----------------|----------|----------|
| `dataset`      | 3        | IBGE, World Bank or UN statistical tables |
| `government`   | 3        | Laws, regulations, court decisions, official reports |
| `academic`     | 3        | Peer-reviewed papers, theses |
| `organization` | 2        | NGO, industry-association or international-body reports |
| `reference`    | 2        | Encyclopedias, books |
| `news`         | 2        | Journalism |
| `other`        | 1        | Blogs, forums, social media |

Strengths feed the evidence grade (methodology section 6) and live in the scoring
constants file, not in the schema.

## 7. Reference files

### `content/reference/places.json`

Every valid `PlaceCode`, generated once from the ISO 3166-1 list and then
maintained by hand.

```jsonc
[
  { "code": "FR" },
  { "code": "GF", "sovereign": "FR" },   // territory → sovereign state
  { "code": "PY" }
]
```

- Place **names** are not stored. They come from `Intl.DisplayNames` in the build
  locale ("Guiana Francesa" / "French Guiana").
- v1 adds `population` (from a World Bank snapshot) for population-weighted
  exclusivity (methodology section 12).

### `content/reference/brazil-states.json`

```jsonc
[ { "code": "SP", "name": "São Paulo" }, … ]      // 27 entries
```

State names are proper nouns, identical in every locale.

## 8. Status lifecycle

| `status`    | Meaning                          | Dev server           | Preview deploys      | Production    |
|-------------|----------------------------------|----------------------|----------------------|---------------|
| `mock`      | Fake data for building the site  | shown, with a banner | shown, with a banner | **build fails** (J060) |
| `draft`     | Real, research in progress       | shown, with a banner | shown, with a banner | excluded      |
| `published` | Researched and reviewed          | shown                | shown                | shown         |

Banner labels are UI strings (pt-BR: "DADOS FICTÍCIOS", "RASCUNHO").

Extra rules for **mocks**: every source URL must be on `https://example.org/` (J033).
Non-mock items must not use `example.org`. This makes it impossible for a mock
source to point at a real document, and for a real item to keep a placeholder.

`data/index-results.csv` includes every status, with a `status` column.

## 9. Derived data (never stored)

Computed from the files by pure functions:

| Value               | Computed by                                   |
|---------------------|-----------------------------------------------|
| `placeCount`        | presence levels × `PRESENCE_WEIGHTS` (low/point/high) |
| `exclusivity`       | methodology 3.1                               |
| `rarity`, `score`, `scoreLow`, `scoreHigh` | methodology 4–5        |
| `evidenceGrade`     | methodology 6                                 |
| `hiddenJabuticaba`  | `awareness` range high end ≤ 1                 |
| `sovereignStates`   | presence places mapped through `places.json`  |
| `availableLocales`  | which locale files exist                      |
| `backlinks`         | reverse of every other item's `related`       |
| rank                | order by `score`, then by `id` for a stable tie-break |

## 10. Validation

Three layers, all runnable with `pnpm validate` (fast, no Astro build needed):

1. **Shape:** the Zod schemas, per file. Astro's content collections import the
   same schemas, so the dev server reports the same errors.
2. **Integrity:** cross-file rules (table below), in one pure TypeScript module,
   unit-tested with fixture folders of good and bad items.
3. **Environment:** rules that depend on the build target (production vs. preview).

Output format, one line per problem:

```
ERROR J020 content/jabuticabas/capybara/item.json presence[3].place: "XX" is not a known place code.
      Fix: use an ISO 3166-1 alpha-2 code listed in content/reference/places.json.
```

### Rules

Scope: **all** = every status; **pub** = `published` only (a warning for `draft`).

| Code | Level   | Scope | Rule |
|------|---------|-------|------|
| J001 | error   | all   | Folder name equals `id`. |
| J002 | error   | all   | A folder contains only `item.json` and `<locale>.md` files for supported locales. |
| J003 | error   | all   | Each file matches its Zod schema. |
| J010 | error   | all   | `slug` is unique per locale. |
| J011 | error   | all   | `related` ids exist, are not the item itself, and have no duplicates. |
| J020 | error   | all   | `place` exists in `places.json`. |
| J021 | error   | all   | `place` is not `BR`. |
| J022 | error   | all   | `place` is unique within `presence` (likewise `state` within `brazilStates`). |
| J023 | error   | all   | In a level range, `low` is below `high`. |
| J024 | warning | all   | `place` has no geometry in `world.topo.json` (too small for the map). It still counts, but isn't drawn. |
| J030 | error   | all   | Every cited source id exists: evidence lists and body citations. |
| J031 | error   | pub   | Every source is cited at least once. |
| J032 | error   | all   | Source ids are unique within the item. |
| J033 | error   | all   | Mock items use only `example.org` URLs; other items never do. |
| J034 | error   | pub   | Every source has an `archiveUrl`. |
| J035 | error   | pub   | Every input has at least one source, or is `editorial: true`. |
| J036 | error   | all   | `editorial: true` inputs have an empty `sources` list. |
| J040 | warning | all   | `intensity.value` doesn't match the band of `intensity.ratio`. |
| J041 | warning | all   | `intensity` is 4 while `placeCount` > 20. |
| J042 | warning | pub   | `methodologyVersion` is older than the current methodology. |
| J043 | warning | pub   | `lastReviewed` is more than 2 years ago. |
| J044 | error   | all   | `lastReviewed` is not in the future. |
| J050 | error   | all   | `pt.md` exists. |
| J051 | error   | all   | Exactly one locale file has `translationStatus: original`. |
| J052 | error   | all   | All locale files of an item have the same frontmatter keys, including `presenceNotes` keys. |
| J053 | error   | all   | `presenceNotes` keys exist in `presence`. |
| J054 | error   | all   | `jabuticaba:<id>` links in the body point to existing items. |
| J055 | warning | all   | The body contains external links; prefer citations. |
| J056 | error   | all   | The body contains no `#` (h1) heading. |
| J060 | error   | prod  | No item has `status: mock`. |
| J070 | error   | CI    | `schemas/item.schema.json` matches the Zod schema. |
| J071 | error   | CI    | `data/index-results.csv` matches the computed results. |
| J072 | error   | CI    | `data/geo/world.topo.json` matches the `geo:build` output. |

Rule codes are stable. A removed rule's code is never reused.

## 11. Implementation notes

- Two Astro content collections, both using the `glob()` loader from the Content
  Layer API, defined in `src/content.config.ts`:
  - `items`: `content/jabuticabas/*/item.json`
  - `itemTexts`: `content/jabuticabas/*/*.md` (entry id = `<item-id>/<locale>`)
- The Zod schemas live in one module (e.g. `src/schema/`) that imports nothing from
  Astro. `pnpm validate`, `pnpm index`, the tests and the Astro config all import
  from it.
- The JSON Schema is generated with Zod's built-in JSON Schema export.

## 13. Open questions

1. **One category per item**, or one primary category plus free tags? Proposed: one
   category for now; tags can be added later without breaking anything.
2. **Images** (license, author, attribution) are left for a later schema version,
   once the design needs them.
3. **Should drafts appear in preview deploys?** Proposed: yes, with a banner, so
   research in progress can be reviewed.
